## 1. Core identity

**Breure.ai builds focused custom software for maritime workflows.**

Dutch: **Breure.ai bouwt gerichte custom software voor maritieme workflows.**

### Primary audience

- charterers
- contractors
- brokers
- maritime operators
- maritime companies with repetitive technical or operational workflows

### Core idea

**One problem. One focused tool.**

**Eén probleem. Eén gerichte tool.**

Breure.ai solves specific operational problems. It does not sell giant software
transformations, industry-wide platforms, or “we do everything digital”.

### Factual entity statements (GEO)

Use language like this — concrete, true, easy for humans and AI systems to parse:

- Breure.ai builds focused custom software for maritime workflows.
- Breure.ai develops tools for charterers, contractors and brokers.
- The Vessel Comparison Tool is a demonstration of software for comparing vessel capabilities and technical data.

Avoid empty marketing: “revolutionizing maritime with next-generation AI.”

## 4. Product philosophy

Do not default to building large platforms.

1. One concrete workflow
2. One painful repetitive problem
3. The smallest useful software solution
4. Real-world testing
5. Expansion only when justified

A small tool that removes hours of manual work can be more valuable than a large
platform nobody wants to use.

Avoid software bloat. Do not add features merely because they are technically possible.

Public process (keep this shape unless strategy changes):

1. Show the workflow / problem
2. Reduce scope
3. Build a first working version
4. Test with real work
5. Improve what matters

---

## 5. Speed

AI-assisted development and modern tooling help Breure.ai build quickly.

**Do not promise that every project is finished within one week.**

Preferred principle:

> For tightly scoped workflows, a first working version can often be ready within days rather than months.

Speed comes from narrow scope, reusable engineering patterns, modern tooling,
AI-assisted development, and rapid iteration — not from cutting quality.

Do not revive old 4–12 week website-agency timelines. Those belong to a previous identity.

---

## 6. AI positioning

AI is an enabling technology. **AI is not automatically the product.**

Breure.ai is not a generic AI agency.

**The customer buys useful software, not AI terminology.**

Use AI when it improves extraction, classification, automation, search, document
processing, decision support, or development speed.

Do not insert AI into a workflow merely to sound modern. Do not overuse “AI” on the public site.

## 14. Design principle

Breure.ai software should not merely function. It should be well designed.

Dashboards, calculators, comparison tools and internal software need deliberate UX/UI.
Do not treat internal business software as an excuse for ugly interfaces.

Priority:

1. Clear user experience
2. Reliable functionality
3. Strong visual design
4. Performance
5. SEO / GEO where applicable

Public marketing pages: visual design remains extremely important.
Do not turn the website into a generic SaaS template.
Do not perform a full visual redesign unless required.

## 16. Technical philosophy

Preserve the existing stack unless there is a genuine reason to change it.

- Next.js (App Router), React, TypeScript, Tailwind CSS
- Package manager: **pnpm** (not npm)
- Reusable components, clean architecture, performance, accessibility, responsive design, semantic HTML
- Do not introduce large dependencies without a reason
- Do not refactor stable code simply because an agent prefers another pattern

Bilingual site: Dutch default, English under `/en`. Language switching must stay intact.
